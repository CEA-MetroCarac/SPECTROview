## **Поддерживаемые форматы данных** { #supported-data-formats }

Примеры всех поддерживаемых типов данных можно найти в папке [`/examples`](https://github.com/CEA-MetroCarac/SPECTROview/tree/main/examples) репозитория GitHub. Вы можете скачать эти файлы, чтобы ознакомиться с поддерживаемыми форматами и структурой данных, а также попрактиковаться в работе со **SPECTROview** на реальных данных.

| Формат | Расширение | Загрузчик | Тип данных |
|---|---|---|---|
| Текст с разделителями | `.txt`, `.csv` | Автоопределение разделителя и заголовка | Одиночные спектры, 2D-карты, карты пластин и карты с временным разрешением |
| Renishaw WiRE | `.wdf` | Встроенный модуль чтения бинарных файлов | Одиночные спектры, временные серии, линейные профили и 2D-карты |
| HORIBA LabSpec 6 | `.l6s`, `.l6m` | Встроенный модуль чтения бинарных файлов | Одиночные спектры (`.l6s`) и гиперспектральные 2D-карты (`.l6m`) |
| HORIBA LabSpec 5 | `.ngs`, `.ngc` | Встроенный модуль чтения бинарных файлов | Одиночные спектры (`.ngs`) и сжатые гиперспектральные 2D-карты (`.ngc`) |
| SPC | `.spc` | Встроенный модуль чтения бинарных файлов | Одиночные спектры и 2D-карты |
| TRPL | `.dat` | Встроенный парсер | Кривые затухания фотолюминесценции с временным разрешением |
| Табличные данные | `.xlsx`, `.xls`, `.csv` | `Pandas` & `Openpyxl` | Таблицы DataFrame для построения графиков |
| Шаблон модели аппроксимации | `.json` | **Модель аппроксимации** (Fit Model Builder) | Модели пиков и конфигурация базовой линии |

### **1. Форматы `.wdf` (Renishaw), `.spc`, `.l6s` / `.l6m` (HORIBA LabSpec 6) и `.ngs` / `.ngc` (HORIBA LabSpec 5)** { #1-wdf-renishaw-spc-l6s-l6m-horiba-labspec-6-and-ngs-ngc-horiba-labspec-5-formats }

**SPECTROview** нативно поддерживает бинарные форматы спектрометров и не требует установки стороннего ПО от производителей:

- **`.wdf`** — данные, зарегистрированные в программном обеспечении WiRE на приборах Renishaw (дискретные спектры, временные серии / серии повторяемости, профили 1D-сканирования вдоль линии и гиперспектральные 2D-карты).
- **`.l6s` и `.l6m`** — собственные бинарные спектры (`.l6s`) и спектральные 2D-изображения/карты (`.l6m`), как несжатые, так и сжатые, записанные в программном обеспечении HORIBA LabSpec 6.
- **`.ngs` и `.ngc`** — собственные бинарные спектры (`.ngs`) и сжатые спектральные 2D-изображения/карты (`.ngc`), записанные в программном обеспечении HORIBA LabSpec 5.
- **`.spc`** — данные, записанные с помощью ПО LabSpec 6 / T64000 / GRAMS на приборах HORIBA и Thermo (дискретные рамановские/PL-спектры и гиперспектральные 2D-карты).

Как дискретные спектры, так и гиперспектральные наборы данных автоматически направляются в нужную рабочую область при открытии или перетаскивании в главное окно без предварительного преобразования. **SPECTROview** также считывает и импортирует **метаданные** прибора (длину волны возбуждения, дифракционную решётку, объектив, мощность лазера, время экспозиции, число накоплений, размер щели/конфокального отверстия, спектральные единицы, шаги пространственного сканирования, временные метки регистрации и дополнительные параметры оборудования, такие как модель и температура детектора, режим SWIFT и отношение сигнал/шум S/N).

### **2. Спектроскопические данные (`.txt`, `.csv`)** { #2-spectroscopic-data-txt-csv }

**SPECTROview** поддерживает одномерные (1D) спектроскопические данные в форматах TXT и CSV. Файлы должны содержать **два числовых столбца данных**, разделённых точкой с запятой (`;`), запятой (`,`), табуляцией или пробелами. Начальные строки комментариев (`#`) и заголовки столбцов являются необязательными и определяются автоматически без потери первой точки данных в файлах без заголовка:

- **Столбец 1**: значения по оси X (например, рамановский сдвиг в см⁻¹, длина волны в нм, 2θ в градусах). Убывающая шкала X автоматически сортируется по возрастанию.
- **Столбец 2**: соответствующие значения интенсивности (отн. ед.).

### **3. Гиперспектральные данные (`.txt`, `.csv`)** { #3-hyperspectral-data-txt-csv }

**SPECTROview** поддерживает гиперспектральные данные (2D-карты предметного столика, карты пластин и многопроходные карты пластин с временным разрешением) в форматах TXT и CSV со следующей структурой:

| X    | Y    | R1 | R2 | R3 | ... | Rn |
|------|------|----|----|----|-----|----|
| **X1** | **Y1** | i1 | i1 | i1 | ... | i1 |
| **X2** | **Y2** | i2 | i2 | i2 | ... | i2 |
| **...** | **...** | ... | ... | ... | ... | ... |
| **Xn** | **Yn** | in | in | in | ... | in |

- **Первая строка** (R1 → Rn) задаёт общие для всех спектров значения по оси X (например, рамановский сдвиг в см⁻¹).
- **Первые два столбца** задают пространственные координаты X и Y каждого спектра на карте.
- **Остальные столбцы** (со второй строки по последнюю) содержат соответствующие значения интенсивности для каждого спектра (I1 → In).

> **Примечание**: Нативные файлы карт Renishaw `.wdf` можно загружать непосредственно в **SPECTROview** без преобразования. Текстовые 2D-карты в длинном формате, экспортированные из Renishaw WiRE (со столбцами `#X`, `#Y`, `#Wave`, `#Intensity`), можно преобразовать в широкий матричный формат `.txt` с помощью функции `spectroview.api.io.convert_renishaw_map(input_path, output_path)`.

### **4. Таблицы данных (Excel или CSV)** { #4-datasheet-excel-or-csv }

Файлы Excel (`.xlsx`, `.xls`), содержащие один или несколько листов, а также файлы CSV можно импортировать непосредственно в рабочую область **Графики** (Graphs) для немедленной визуализации и построения графиков.

### **5. Собственные форматы SPECTROview** { #5-native-spectroview-formats }

Чтобы рабочий процесс можно было сохранить и продолжить позже, **SPECTROview** использует специальные расширения файлов в зависимости от активной рабочей области:

- Рабочая область **Карты** (Maps) → `.maps`
- Рабочая область **Спектры** (Spectra) → `.spectra`
- Рабочая область **Графики** → `.graphs`
- **Шаблоны моделей аппроксимации** → `.json` (перетаскивание или кнопка **Загрузить** (Load) в рабочих областях **Спектры** и **Карты**)
